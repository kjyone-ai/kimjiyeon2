# 평가 대비 설명 (항목 2~4)

## 항목 2. 코드 구조 및 설계

1. **함수 분리 기준**: "사용자가 메뉴에서 고르는 기능 하나 = 함수 하나"로 나누고, 여러 기능이 같이 쓰는 로직(입력 검증, 조건 필터링, 한 줄 출력)은 도우미 함수로 뺐다. 역할은 README의 코드 구조 표 참고.
2. **데이터 구조**: `{"title","content","category","favorite","views"}` 딕셔너리를 리스트에 담는다. 필드는 `prompt["title"]`처럼 키로 접근하고, 목록 번호는 `enumerate(prompts, start=1)`의 번호(= 인덱스+1)를 쓴다.
3. **입력 검증 위치**: 파일 맨 위 `input_non_empty()`(빈 값이면 재입력), `input_number(msg, min, max)`(숫자가 아니거나 범위 밖이면 안내 후 `None` 반환), `input_unique_title()`(제목 중복 시 재입력). 기능 함수는 직접 검증하지 않고 이 함수를 호출하므로 검증 규칙이 한 곳에만 있다. 메뉴 번호는 `actions` 딕셔너리에 없으면 "잘못된 입력" 처리.
4. **커밋 기준**: 기능 하나가 동작하는 단위로 커밋하고(추가/목록, 조회/검색, 상세/즐겨찾기, 저장/내보내기, 수정/삭제/Top), 기능별 브랜치에서 작업한 뒤 병합 커밋으로 남겼다. 접두어는 `feat`/`chore`/`docs`/`merge`.

## 항목 3. 핵심 기술 원리

1. **리스트 + 딕셔너리**: 리스트는 순서가 있어 "번호로 선택", 추가/삭제, 정렬이 쉽다. 딕셔너리는 필드를 이름으로 접근해 가독성이 좋고 필드 추가(`views`)가 쉽다. 단점은 리스트 검색이 O(n)이고 오타 키는 런타임에 발견된다는 점이지만, 수십~수백 개 규모의 개인용 프로그램에서는 문제없다. JSON으로 그대로 저장되는 것도 장점이다.
2. **while**: 사용자가 종료를 선택할 때까지 횟수를 알 수 없이 반복해야 하므로 `while True`를 쓴다. 종료 조건은 입력이 `"0"`일 때 `break`. 잘못된 입력은 종료하지 않고 안내 후 다음 반복으로 넘어간다. Ctrl+C/EOF도 `try/except`로 정상 종료 처리한다.
3. **제목 또는 내용 검색**: 키워드와 제목/내용을 모두 `.lower()` 한 뒤 `keyword in title or keyword in content`(문자열 포함 연산)로 검사한다. `find_prompts(prompts, 조건함수)`가 조건을 만족하는 항목을 전체 번호와 함께 돌려준다.
4. **브랜치**: 기능마다 `feature/*` 브랜치를 만들어 작업 중 코드가 안정 버전을 깨지 않게 했다. 병합 기준은 "그 기능을 직접 실행해 확인했고, 기존 메뉴가 그대로 동작함"이며, 기능 완료 시점마다 `--no-ff`로 병합해 기능 단위 이력이 그래프에 남게 했다.

## 항목 4. 심층 인터뷰

1. **영속화**: 종료 시 메모리가 사라지므로 파일에 저장해야 한다. 이 프로그램은 **JSON**을 선택했다(리스트/딕셔너리 구조 그대로 저장, 사람이 읽을 수 있고 표준 라이브러리 `json`으로 충분). 시작 시 `load_prompts()`, 변경 시 `save_prompts()`, 파일 없음/깨짐은 기본 데이터로 대체한다. CSV는 줄바꿈이 있는 내용 처리가 번거롭고, DB(SQLite)는 이 규모에는 과하다. 데이터가 커지면 SQLite로 옮긴다.
2. **같은 제목**: 현재 규칙은 **대소문자 무시 중복 금지**다. 추가·수정 시 `title_exists()`로 검사해 재입력받는다. 대안은 "(2)" 같은 번호를 자동으로 붙이는 방식이나 고유 `id` 필드를 두는 방식이며, 삭제/수정이 번호가 아닌 id 기준이 되어 더 안전하다.
3. **병합 충돌**: ① 원인 파악: `git status`와 파일의 `<<<<<<<`/`=======`/`>>>>>>>` 표시로 어느 파일의 어느 부분이 양쪽에서 바뀌었는지, `git log --merge`/`git diff`로 각 변경의 의도를 확인. ② 해결: 두 변경을 모두 살려 수동 편집, 표시 제거 후 `git add`, `git commit`. ③ 검증: 프로그램을 실행해 양쪽 기능을 모두 확인하고 `git log --graph`로 병합 기록 확인. 막히면 `git merge --abort`.
4. **카테고리 변경**: 카테고리 목록은 `CATEGORIES` 상수 한 곳에만 있고, 선택 메뉴·조회·내보내기는 모두 이 상수(와 데이터에서 파생된 `get_all_categories()`)를 읽는다. 따라서 `CATEGORIES`만 수정하면 되고, 이미 저장된 데이터의 옛 카테고리는 `get_all_categories()`가 자동으로 목록에 포함해 사라지지 않는다. 이름을 바꿀 때는 기존 JSON 데이터의 카테고리도 함께 변환(마이그레이션)해야 한다.
